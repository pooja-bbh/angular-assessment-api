# Internationalisation (i18n) Rules

## Readiness
- The application does not need to ship with multiple languages for this assessment, but the codebase must be i18n-ready so translations can be added later without refactoring.
- Use Angular's built-in i18n (`@angular/localize`) as the foundation.

## Strings
- Never hardcode user-visible strings in templates or TypeScript.
- Never concatenate translated strings using the `+` operator — use template interpolation or ICU message format instead.

## Dates & Currency
- Use Angular's built-in `DatePipe` for all date formatting.
- Use Angular's `CurrencyPipe` for all currency formatting.
- Always display the currency code or symbol alongside every monetary amount.
- Never assume a single currency or locale number format.
